# 工程型本科论文 Checklist（34 条）

**适用范围**：南京大学软件工程专业本科软件系统型毕业论文。
**条目分布**：4 红线 + 10 学术质量 + 10 结构内容 + 4 格式细节 + 6 参考文献。
**ID 命名**：UND-RED-N（红线）/ UND-ENG-A-NN（学术质量）/ UND-ENG-B-NN（结构）/ UND-ENG-C-NN（格式）/ UND-ENG-F-NN（参考文献）。

## 🔴 红线（4 条）

### UND-RED-1：标题/目录/摘要无错别字

```yaml
id: UND-RED-1
类别: 红线
对应 PDF 要点: 13（摘要/标题/目录无错别字）
问题: "标题、目录、摘要中是否出现错别字（PDF 第 5 页明示这是零容忍项）"
检查方法: |
  1. Read 骨架前 100 行（含封面、摘要、目录）
  2. 与 PDF 题目对照：题目中的字逐字校对（题目是错别字高发区，常见"系统"误为"系绕"、"实现"误为"试现"等）
  3. 摘要内容做语义连贯性检查：找无意义的字符序列、不通顺的短语
  4. 目录章节名与正文实际章节名比对
评判标准:
  通过: 无错别字
  警告: 仅在内文（非标题/目录/摘要）发现错别字
  不合格: 标题、目录、摘要中至少有 1 个错别字
修改建议模板: "在 §X 处的'YYY'疑为'ZZZ'之误，建议核对后修正。标题/目录/摘要的错别字会直接拉低评审印象分。"
```

### UND-RED-2：正文字数 ≥ 15,000

```yaml
id: UND-RED-2
类别: 红线
对应 PDF 要点: 4（字数 ≥ 15,000）
问题: "正文字数（含图表说明，不含封面/目录/致谢/参考文献）是否 ≥ 15,000"
检查方法: |
  1. 从骨架元信息读正文起止页（一般是绪论第一章首页到结论末页）
  2. 估算字数：page_count × 平均字符密度（中文论文约 400-500 字/页，宁可估保守值 380）

  4. 若估算在 13,500-15,000 之间 → 警告（边界，建议精确统计）

  警告: 估算 13,500-16,000
  不合格: 估算 < 13,500
修改建议模板: "正文页数 X-Y（共 N 页），按平均 380 字/页估算约 NN,000 字，未达 15,000 底线。建议在 §X.Y 章节扩充约 N,NNN 字（具体扩充方向见报告）。"
```

### UND-RED-3：软件系统六要素完整

```yaml
id: UND-RED-3
类别: 红线
对应 PDF 要点: 9（软件系统六要素：需求 → 架构 → 模块 → 数据库 → 代码 → 运行截图）
问题: "六大要素是否齐全：需求分析 / 系统架构 / 模块设计 / 数据库设计 / 代码实现 / 运行截图"
说明: |
  PDF 第 14 页要求的是"内容要素"齐全，而非必须有 6 个独立顶级章节。
  这些要素可以以章、节（§X.Y）、甚至小节（§X.Y.Z）的形式承载，
  也允许多个要素合并到一章（如"系统设计"章同时覆盖架构 + 模块 + 数据库）。
  判定标准是"内容是否实际呈现"，不是"标题是否独立成章"。
检查方法: |
  1. 在骨架的章节 + 子节标题中 grep（不限于顶级章），匹配以下 6 个要素的关键词组（任一即可）：
     - 需求：'需求分析' | '功能需求' | '需求建模' | '用例分析'
     - 架构：'系统架构' | '系统设计' | '总体设计' | '架构设计' | '总体架构'
     - 模块：'模块设计' | '详细设计' | '模块实现' | '功能模块' | '组件设计'
     - 数据库 / 持久化 / 数据流：'数据库设计' | '数据库实现' | '数据模型' | 'E-R' | '数据存储' | '数据表' | '持久化' | 'JSON' | 'SQLite' | 'LocalStorage' | 'IndexedDB' | 'LevelDB' | 'RocksDB' | '本地文件' | '配置文件' | 'S3' | 'OSS' | '数据流' | '数据流向' | '数据处理' | '数据集'（数据量不大时允许用非数据库的持久化方案；**实时算法/感知类模块**可完全无持久化，仅需描述数据流向 + 中间数据结构 — 详见 B-08 路径 C）
     - 代码：'代码实现' | '关键代码' | '核心实现' | '系统实现' | '编码实现'
     - 截图：'运行截图' | '系统测试' | '系统展示' | '功能演示' | '部署运行' | '运行效果' | '运行界面' | '界面示例' | '界面截图' | '渲染效果图' | '展示页面' | '页面示例' | '功能性测试' | '非功能性测试' | '示意图' | '操作示意图' | '数据示意图'（基于 24-25 年优秀论文实证：截图载体词有多种合规形式："界面示例"、"渲染效果图"、"操作示意图"、"数据示意图"、"功能测试"等，散落在实现章/测试章；袁家乐《软件成分分析系统》全部用"操作示意图"作为子节标题）
  2. 若标题层 grep 未命中某要素，回退到正文内容层：用 pdfplumber 在正文中搜索该要素的核心内容特征
     （如数据库要素：是否出现 E-R 图、数据表结构、字段定义；截图要素：是否有"图 X-Y 系统运行界面"
     等图题）。正文层命中也算该要素存在。
  3. 标题层 + 内容层都未发现某要素 → 该要素缺失 → 红线命中
评判标准:
  通过: 6 个要素均有承载（章、节、子节、或正文内容均可）
  警告: 不适用（要素真缺直接进入不合格）
  不合格: 缺 ≥ 1 个要素（且正文内容层也未呈现）
修改建议模板: |
  "本论文未发现 'XX' 要素的内容承载（既无相关章节标题，也未在正文中呈现 XX 的核心内容）。
  PDF 第 14 页明确该要素'缺一不可'。建议补充：
   - 若已有相近章节，可在其下增加 §X.Y 子节承载该要素；
   - 若完全缺失，建议新增一章/节，篇幅至少 P 页/Q 段。
  注意：不强制独立成章，但内容必须实际出现。"
团队论文 override: 见 team-submodule-overrides.md Patch 1
```

### UND-ENG-A-05：表题在表上方、图题在图下方

```yaml
id: UND-ENG-A-05
类别: 学术质量
对应 PDF 要点: 5
问题: "标题位置：表上、图下；算法/代码块标题位置由其归属的体系决定（A 上 / B 下）"
说明: |
  基于 25 年本科优秀论文实证：
   - **图**（架构图、流程图、数据图、效果图）：标题在**下方**，编号"图 X-Y"
   - **表**（数据表、对照表、用例表、测试用例表）：标题在**上方**，编号"表 X-Y"
   - **算法 / 代码块**：标题位置取决于作者所选体系（参见 UND-ENG-A-06、UND-ENG-C-01）：
     · 体系 A（独立"算法 N / 代码 N"全局连续整数）：标题在**上方**（按表对待）
       — 来源：李薛成《结合符号执行的大模型制导生成程序测试》
     · 体系 B（"图 X-Y XX算法/代码示例"，归入插图目录）：标题在**下方**（按图对待）
       — 来源：徐子豪《基于 OpenRL 框架的雷达博弈仿真软件...》
     · 体系 C（独立"代码 X.Y / 算法 X.Y"章号.序号，点号分隔）：标题在**上方**
       — 来源：王铭嵩《SELABS 中综合资产管理模块的设计与实现》
  关键判定：**位置应与所选体系一致**，而非绝对要求"上"或"下"。
检查方法: |
  1. 在骨架中找标记：'图\s*\d+-\d+'、'表\s*\d+-\d+'、'算法\s*\d+\s'、'代码\s*\d+\s'
  2. 由于 PDF 难以直接判断"上方/下方"，转用启发式：
     - 提取每个块所在页面的文字布局
     - 用 pdfplumber 的 char.top 属性比较标题文字 y 坐标 vs 块本身 bbox
  3. 对算法/代码块：先识别采用的是体系 A 还是体系 B，再核对标题位置是否与体系一致
  4. **无表格论文豁免**：若全文 grep '表\s*\d+-\d+' 命中数为 0（且"表格目录"页空白），
     视为本论文不含表，跳过表标题位置检查。例：陈凯文《超大型云数据中心网络中路由条目
     可扩展性的研究》整篇论文只有图无表，不影响优秀评级。
  5. 如难以自动判断 → 警告，提示人工核对
评判标准:
  通过: 图标题在下、表标题在上（无表格论文跳过表检查）；算法/代码标题位置与所选体系一致
  警告: 1-2 处位置错误 或 体系与位置不匹配
  不合格: ≥ 3 处位置错误 或 无法判断
修改建议模板: |
  "标题位置抽查结果：
   - 图 X-Y 标题疑似在上方（应在下方）；
   - 表 X-Y 标题疑似在下方（应在上方）；
   - 代码块采用体系 [A / B]，标题应在 [上方 / 下方]，但实际疑似在 [位置]；
  建议核对所有图/表/算法/代码块的标题位置一致性。"
团队论文 override: 无
```

### UND-ENG-A-06：图表/公式/算法/代码 编号规范

```yaml
id: UND-ENG-A-06
类别: 学术质量
对应 PDF 要点: 5
问题: |
  编号规范分两层：
  (确定层) 图、表、公式必须按 **X-Y** 格式编号（X 为章号，Y 为该章内序号），各自独立连续；
  (灵活层) 算法、代码块允许三种编号体系，作者择一并保持一致：
   - 体系 A（学术偏好）：独立全局连续整数编号（"算法 4"、"代码 1"），不带章号；
   - 体系 B（工程独立论文偏好）：归入图体系，按"图 X-Y XX算法/代码示例"编号，进入插图目录；
   - 体系 C（工程团队子模块论文偏好）：独立章号.序号编号（"代码 4.1"），点号分隔，各章内连续。
说明: |
  基于 25 年本科优秀论文实证：
   - 李薛成（学术型）：图/表/公式 X-Y 章号-序号；算法/代码独立全局连续 — 体系 A
   - 徐子豪（工程独立）：图/表/公式 X-Y 章号-序号；代码归入"图 X-Y XX代码示例" — 体系 B
   - 王铭嵩（工程团队）：图/表 X-Y 章号-序号；代码独立"代码 4.1" 章号.序号 — 体系 C
  这说明算法/代码块的编号是**作者风格选择**，三种都不算违规。
  检查重点是**一篇论文内保持一致**，不要混用。
检查方法: |
  1. 确定层 — grep 全骨架的：
     - '表\s*\d+-\d+'、'图\s*\d+-\d+'、'\(\d+-\d+\)'（公式）
     - 提取编号按章号分组，每章内 Y 应从 1 开始连续递增
     - 不允许跨章共用编号
     - **无表格论文豁免**：若 grep '表\s*\d+-\d+' 命中数为 0（且"表格目录"页为空白），
       跳过表编号检查，仅检查图/公式（基于陈凯文《超大型云数据中心网络中路由条目
       可扩展性的研究》实证 — 整篇优秀论文可只有图无表）
  2. 灵活层 — 算法/代码块（先识别体系，再分别检查）：
     - 若 grep '算法\s*\d+\s' 或 '代码\s*\d+\s' 命中（编号是纯整数 N）→ 体系 A，检查全文连续
     - 若 grep '图\s*\d+-\d+.*(?:算法|代码|实现).*(?:示例|关键代码|示意|实现)' 命中 → 体系 B，已被确定层覆盖
       （体系 B 的代码块描述词有多种合规形式：'代码示例' / '关键代码' / '实现示例' / '代码实现' 等）
```

### UND-ENG-C-01：代码块呈现规范（三种合规体系任选其一）

```yaml
id: UND-ENG-C-01
类别: 格式细节
对应 PDF 要点: 6（PDF 第 9 页"代码呈现规范"）
问题: |
  论文中的代码块是否符合任一合规体系：等宽字体 + 编号 + 标题位置一致 + 正文有引用。
  共同要求：
   - 等宽字体（Consolas / Source Code Pro / Courier New 等），可带行号、关键词加粗；
   - **不需要** 1×1 表格；
   - 必须有图题/标题，且在正文至少被引用一次；
   - 一篇论文内**保持单一体系**，不要混用。
说明: |
  基于 25 年本科优秀论文实证，代码块**三种体系并存且均合规**：

  ▸ **体系 A（学术型偏好）**：独立"代码 N"全局连续整数编号，**标题在上方**（按表对待）
    代码 1  符号规格模板示例
      1  #include "klee/klee.h"
      2  int main(){...}
    （来源：李薛成《结合符号执行的大模型制导生成程序测试》）
    通常论文不为代码块单建"代码目录"，但有独立算法 / 代码标题体系。

  ▸ **体系 B（工程论文偏好，独立或团队子模块均可）**：归入插图体系，**标题在下方**（按图对待）
    描述词有多种合规形式（任一均可）：
     · "图 X-Y XX 代码示例"（徐子豪《基于 OpenRL 框架的雷达博弈仿真软件...》）
     · "图 X-Y XX 关键代码"（袁家乐《软件成分分析系统漏洞与许可证分析模块的设计与实现》）
     · "图 X-Y XX 实现示例" / "图 X-Y XX 代码实现"
    格式实例：
       [code block]
       图 5-1  PPONet 实现的代码示例
    或：[code block]
       图 4-2  NVD 漏洞数据收集关键代码
    所有代码块标题列入论文前面的"插图目录"中。

  ▸ **体系 C（工程团队子模块论文偏好）**：独立"代码 X.Y"章号.序号编号（点号分隔），**标题在上方**
    代码 4.1: 添加耗材领用申请核心代码
      [code block]
    （来源：王铭嵩《SELABS 中综合资产管理模块的设计与实现》）
    与体系 A 类似（独立体系 + 标题在上方），但编号带章号。

  自动检查时不要强行判定哪种"更正确"，只要保持单一体系且呈现规范即可。
检查方法: |
  1. 在骨架/正文中找代码片段（特征：等宽字体、连续多行、含 `;`/`{}`/`def`/`function` / `int main` / `#include` / `class` / `@Override` 等）
  2. 识别采用的是哪种体系：
     - grep '代码\s*\d+\s' 命中（不含 `.` 不含 `-`）→ 体系 A
     - grep '图\s*\d+-\d+.*(?:代码示例|关键代码|实现示例|代码实现)' 命中 → 体系 B
     - grep '代码\s*\d+\.\d+' 命中（含点号）→ 体系 C
     - 若多种都命中 → 警告（混用不规范）
  3. 按对应体系检查每段代码：
     - 体系 A：标题是否在**上方**、编号是否全局连续整数
     - 体系 B：标题是否在**下方**、编号是否符合 X-Y 章号-横线-序号、是否进入"插图目录"
     - 体系 C：标题是否在**上方**、编号是否符合 X.Y 章号-点号-序号且各章内连续
     - 共同：等宽字体、正文至少引用 1 次
评判标准:
  通过: 单一体系（A、B 或 C 之一）+ 等宽字体 + 标题位置正确 + 正文有引用
  警告: 1-2 段代码无编号 / 字体不等宽 / 标题位置疑似错误 / 体系混用 1-2 处
  不合格: 全部代码直接贴出，无格式 / 同一论文中多种体系大量混用
修改建议模板: |
  "代码片段（§X 处）：检测到本论文采用 [体系 A '代码 N'] / [体系 B '图 X-Y 代码示例'] / [体系 C '代码 X.Y']，但发现：
   - [具体问题，如：字体不等宽 / 标题位置与体系不符 / 正文未引用 / 与主体系不一致]
   建议保持单一体系且按规范呈现。三种体系本身都符合 25 年本科优秀论文实证。"
团队论文 override: 无
```

### UND-ENG-F-06：arXiv / 预印本条目著录格式（GB/T 7714 新旧国标兼容）

```yaml
id: UND-ENG-F-06
类别: 参考文献
对应 PDF 要点: 7、8
问题: |
  参考文献中的 arXiv 预印本条目（含 bioRxiv / SSRN / OpenReview / ChinaXiv 等同类预印本平台）
  是否著录规范。预印本的类型标识有两套国标，**二者均合规、均不报错，建议优先按新国标**：
  - **GB/T 7714—2025（新国标，推荐）**：用 `[PP/OL]`（PP = 预印本，OL = 联机网络）。2025 版新增了
    "预印本"这一文献类型，是当前国标对 arXiv 类文献的标准著录方式。
    模板：`[N] 主要责任者. 题名[PP/OL]. 出版平台, (发表或更新日期)[引用日期]. 获取和访问路径. 永久标识符.`
    示例：`[31] Kimi Team. Attention Residuals[PP/OL]. arXiv, (2026-03-24)[2026-05-22]. https://arxiv.org/abs/2603.15031. arXiv:2603.15031 [cs.CL].`
  - **GB/T 7714—2015（旧国标，兼容）**：用 `[EB/OL]`（按电子资源著录）。新旧标准尚处过渡期，
    学校学位论文模板 / 拟投期刊若仍强制 2015 版，`[EB/OL]` 同样合规、**不报错**。
    模板：`[N] 主要责任者. 题名[EB/OL]. (发表或更新日期)[引用日期]. 获取和访问路径.`
说明: |
  逐条核查四点（无论用哪套标准都要满足）：
   1. **类型标识符**：`[PP/OL]` 或 `[EB/OL]` 均 ✅；标成 `[J]` / `[J/OL]` → ❌——arXiv 论文未经
      同行评议正式发表，不是期刊，标成期刊属实质性著录错误。建议优先改为新国标 `[PP/OL]`。
   2. **两个日期齐全**：`(发表或更新日期)[引用日期]` 都要有，如 `(2026-03-24)[2026-05-22]`。
      漏写引用日期是预印本条目最常见的缺项。
   3. **完整获取路径**：写完整 URL（`https://arxiv.org/abs/XXXX.XXXXX`）或 DOI
      （`https://doi.org/10.48550/arXiv.XXXX.XXXXX`），不能只留裸编号 `arXiv:XXXX.XXXXX` 当获取路径。
   4. **体例前后一致**：同一篇论文文献表里所有 arXiv 条目统一用同一套标准（全 `[PP/OL]` 或
      全 `[EB/OL]`），不要逐条混用；单条之内也不要把 2015 与 2025 两套模板字段拼接。
      **注意**：`[PP/OL]` 格式末尾的永久标识符 `arXiv:XXXX.XXXXX [cs.XX]`（含学科分类号）是
      2025 新国标的规范字段，应当保留——它与正文里的 URL 各司其职，**不要按"编号重复 / 体例
      混搭"误报**。

  本科论文的 arXiv 引用通常远少于硕士版（数量上限由 F-02 兜底 ≤ 10 篇），但 ML / NLP 方向
  本科论文仍可能密集引用 arXiv 预印本，本条仍需逐条核著录格式。
检查方法: |
  1. 在参考文献章用 `grep -inE "arxiv\.org|arxiv:[0-9]{4}\.[0-9]"` 定位全部 arXiv 条目
  2. 核类型标识符：命中 `[PP/OL]` 或 `[EB/OL]` → ✅；命中 `[J]` / `[J/OL]` → ❌
     （建议统一为 `[PP/OL]`）
  3. 核日期：是否同时含发表日期 `(YYYY-MM-DD)` 与引用日期 `[YYYY-MM-DD]`
  4. 核获取路径：条目内是否有 `arxiv.org/abs/` 或 `doi.org/10.48550`；
     仅有裸 `arXiv:XXXX.XXXXX` → ❌
  5. 核体例一致：`grep -oiE "\[PP/OL\]|\[EB/OL\]"` 若两种标识在同一文献表同时出现
     → ⚠️ 体例未统一；`grep -coiE "arxiv:[0-9]{4}\.[0-9]+"` 看同一条目内冒号式裸编号
     `arXiv:XXXX.XXXXX` 是否出现 ≥ 2 次 → ⚠️ 编号重复（URL 里的 `arxiv.org/abs/2603.15031`
     与末尾永久标识符 `arXiv:2603.15031` 各出现一次属正常，不算重复）
评判标准:
  通过: arXiv 条目类型标识正确（[PP/OL] 或 [EB/OL]）、两个日期齐全、获取路径完整、体例统一
  警告: 1-2 条 arXiv 条目著录有缺漏（缺引用日期 / 缺完整 URL / 体例未统一等）
  不合格: ≥ 3 条 arXiv 条目著录错误 或 出现 [J] / [J/OL] 类实质性错标
修改建议模板: |
  "参考文献 [{N}]「{标题}」为 arXiv 预印本，著录有问题：
   {类型标识误用 [J/OL]，应为 [PP/OL]（2025 新国标）或 [EB/OL]（2015 旧国标）/
   日期著录不全（缺发表或更新日期、引用日期）/ 无完整获取路径 URL /
   全表 arXiv 条目 [PP/OL] 与 [EB/OL] 混用，体例未统一 / 同一条目内 arXiv 编号重复出现}。
  **优先按 GB/T 7714—2025 新国标的 [PP/OL] 格式重排**（模板与示例见上）。新旧标准处于过渡期，
  先确认学校学位论文模板或拟投期刊是否已宣布切换至 2025 版：已切换即用 `[PP/OL]`；
  仍强制旧版即退回 `[EB/OL]`。发表日期取 arXiv 该版本的提交日期，引用日期取实际查阅日期。
  若该预印本已被会议 / 期刊正式接收发表，**优先改引正式发表版本**（按 [C] / [J] 著录），
  预印本版仅作兜底。"
与 UND-ENG-F-02 的分工: |
  F-02 管 arXiv 预印本的**数量上限**（≤ 10 篇），本条管每条 arXiv 条目的**著录格式**，
  二者独立计警告。
团队论文 override: 无
```
