# 学术型本科论文 Checklist（31 条）

**适用范围**：南京大学软件学院 / 智能软件与工程学院本科**学术研究型**毕业论文。

## 学术型论文的两种合规子类型

基于 24-25 年优秀论文实证，学术型论文分为两种合规子类型，UND-ACA-S 系列检查时
应区分对待：

▸ **子类型 A：研究方法型（IMRaD 5 章结构）**
  - 例子 1：李薛成《结合符号执行的大模型制导生成程序测试》
  - 例子 2：倪匀博《大语言模型辅助的两阶段编译器测试方法研究》
  - 章节：绪论/引言 → 相关工作/相关技术综述 → 方法/框架设计 → 实验/实验评估 → 总结
  - 特征：相关工作在第二章；含明确的算法/模型；有基线对比（如 HumanEval/EvalPlus、与现有工具的对比）；
    有消融、参数敏感性或案例分析等多种细粒度评估
  - **完整适用** UND-ACA-S-01..05

▸ **子类型 B：系统研究型（多章 motivation + challenge + solution + evaluation 结构）**
  - 例子：陈凯文《超大型云数据中心网络中路由条目可扩展性的研究》
  - 章节：引言 → 技术概述 → 动机 → 挑战 → 数据收集 → 预测 → 解决方案 → 相关工作 → 结论
  - 特征：含独立的"动机"和"挑战"章节；相关工作放在论文末尾（仿 SIGCOMM/NSDI 顶会风格）；
    通常是对真实系统的实证研究；可能没有传统意义上的"基线对比"和"消融实验"
  - **部分豁免** UND-ACA-S-03（基线）和 UND-ACA-S-05（消融）

**章节命名同义说明**：
 - 第一章可命名为 **"引言"** 或 **"绪论"**（同义，两者均合规）
 - 第二章可命名为 **"相关工作"** 或 **"相关技术综述"** 或 **"研究现状"**（同义）
 - 实验章可命名为 **"实验"** 或 **"实验设计"** 或 **"实验评估"** 或 **"实验设计与结果分析"**（同义）
 - 末章可命名为 **"总结"** 或 **"总结与展望"** 或 **"总结和展望"** 或 **"结论"**（同义）
skill 检查时不应限定具体命名，应接受同义变体。

skill 检查时应先识别子类型（grep "动机" / "挑战" 章是否存在 ≥ 2 章），再决定是否豁免。

### UND-ACA-S-01：相关工作章按"方法/路线"分类（位置可前可后）

```yaml
id: UND-ACA-S-01
类别: 学术专属
问题: "相关工作章是否存在且按'方法分类'组织（而非简单时间线罗列），位置在前（第 2 章）或在后（结论前）均合规"
说明: |
  基于 24-25 年优秀论文实证：
   - 子类型 A（研究方法型，李薛成）：相关工作在**第二章**，按方法路线分类
   - 子类型 B（系统研究型，陈凯文）：相关工作在**论文末尾**（结论前），仿 SIGCOMM/NSDI 顶会写法
  两种位置均合规，skill 不应限定相关工作必须在第二章。
  对比表是加分项但不强求（系统研究论文若无表格仍合规）。
检查方法: |
  1. 在全文 grep '相关工作' / '研究现状' / 'related work' / '国内外.*分析' → 确认存在该章
  2. 检查该章是否有清晰的小节分类（§X.1 = 方法 A、§X.2 = 方法 B 等）
  3. 若有表格目录，grep 是否含相关工作章内的对比表
  4. **位置不限定**：第二章或论文末尾均可
评判标准:
  通过: 存在相关工作章 + 按方法分类组织（位置不限）
  警告: 仅按时间线罗列 或 内容过于稀薄
  不合格: 全文无相关工作章 或 < 2 页
修改建议模板: "相关工作章建议按方法分类（如 §X.1 基于规则的方法、§X.2 基于深度学习的方法）。位置可在第二章（方法型论文惯例）或论文末尾（系统研究论文惯例，仿 SIGCOMM/NSDI）。对比表是加分项。"
团队论文 override: 无
```

### UND-ACA-S-02：问题描述清晰（形式化或动机/挑战章节均可）

```yaml
id: UND-ACA-S-02
类别: 学术专属
问题: "是否对要研究的问题做了清晰描述。两种合规形式：(a) 形式化定义（输入/输出/约束/伪代码）；(b) 独立的'动机'+'挑战'章节"
说明: |
  基于优秀论文实证，问题描述有两种合规形式：
   - 子类型 A（方法型，李薛成）：在方法章前部用形式化定义（数学符号 + 伪代码）
   - 子类型 B（系统型，陈凯文）：用独立的'第三章 动机'+'第四章 挑战'两章详细论证
     问题的现实存在性、严重性、解决困难，仿 SIGCOMM 论文风格
  两种形式都能让评审清楚"研究的问题是什么、为什么值得做、为什么难"。
检查方法: |
  1. 形式化形式（任一命中即可）：
     - 在方法章前部 grep '问题定义' / '问题描述' / '形式化' / 'problem formulation'
     - 检查是否含数学符号定义（'X = {x_1, ..., x_n}'、'输入'、'输出'、'目标'）
     - 复杂算法应有伪代码块（grep 'Algorithm' / '算法 \d'）
  2. 动机/挑战形式（任一命中即可）：
     - 全文 grep 章节标题 '动机' / '挑战' / 'motivation' / 'challenge'
     - 这两章合计 ≥ 5 页，含具体数据/案例支撑
  3. 两种形式至少满足一种 → 通过
评判标准:
  通过: 形式化定义齐全 ｜ 或 含动机+挑战章节且论证充分
  警告: 问题描述仅文字，既无形式化也无动机/挑战章节
  不合格: 全文无任何问题定义/动机说明
修改建议模板: |
  "问题描述检查结果：
   - 方法型论文建议在 §X 增加'问题形式化'小节，清晰给出输入/输出/目标，复杂算法配伪代码。
   - 系统研究型论文建议增加独立的'动机'章（用真实数据论证问题严重性）和'挑战'章（论证为什么难），
     这是 SIGCOMM/NSDI 等顶会论文的经典写法。"
团队论文 override: 无
```

### UND-ACA-S-03：实验章含基线方法对比 / 或趋势预测对比（≥ 2 个对比对象）

```yaml
id: UND-ACA-S-03
类别: 学术专属
问题: |
  实验章是否含至少 2 个对比对象。两种合规形式：
   (a) 方法型：≥ 2 个基线方法对比（HumanEval、EvalPlus 等）
   (b) 系统研究型：≥ 2 个真实环境/参考来源对比（如 APNIC 趋势预测 vs 本文预测、不同时间窗对比）
说明: |
  基于优秀论文实证，"对比"在两种学术论文中形态不同：
   - 子类型 A（方法型，李薛成）：与已有 SOTA 方法对比（HumanEval、EvalPlus、KLEE）
   - 子类型 B（系统研究型，陈凯文）：与现有趋势预测对比（APNIC 因特网增长预测 vs 本文 Azure 预测）、
     与无策略基准对比（生产设备仿真在不同 Add-Path 配置下的对比）
  两种"对比"都体现了研究的实证支撑，不应限定必须是"基线方法"。
检查方法: |
  1. 找实验章节，grep '基线' / 'baseline' / '对比方法' / '比较方法' / '对比' / '对照'
  2. 也接受"趋势预测对比"、"参考来源对比"形式：
     grep '预测对比' / '现有.*对比' / '与.*相比' / '不同.*下的'
  3. 统计对比对象数量（不论是基线方法还是参考预测）
评判标准:
  通过: ≥ 2 个对比对象（方法或参考预测均可）
  警告: 仅 1 个对比 或 对比对象单一
  不合格: 无任何对比/对照实验
修改建议模板: |
  "实验章对比检查结果：
   - 方法型论文建议补充 1-2 个 SOTA 基线方法对比。
   - 系统研究型论文建议补充与已有趋势预测/真实环境基准的对比（如对比业界已发布的预测、不同配置下的实测）。"
团队论文 override: 无
```

### UND-ACA-S-04：实验章含评价指标定义 + 数据集来源说明

id: UND-ACA-S-04
类别: 学术专属

检查方法: |
  1. grep '评价指标' / '评估指标' / 'metric' / 'metrics'

### UND-ACA-S-05：细粒度评估（消融/参数敏感性/真实部署/案例分析）（建议项）

```yaml
id: UND-ACA-S-05
类别: 学术专属
问题: |
  是否包含以下任一形式的细粒度评估：
   消融实验 / 参数敏感性分析 / 真实部署评估 / 案例分析
说明: |
  基于优秀论文实证，细粒度评估有多种合规形式（任一即可）：
   - 子类型 A（方法型，李薛成）：消融实验（拆分 SMT 求解 vs 大模型求解的贡献）
   - 子类型 A（方法型，倪匀博）：综合多种细粒度评估（4.4 代码数据库的重要性 = 消融；
     4.5 不同大语言模型的适配性 = 参数敏感性；4.6 迭代轮数的影响 = 参数敏感性；
     4.8 案例分析 = 个案深入讨论）
   - 子类型 B（系统研究型，陈凯文）：真实部署/生产设备评估（在 Azure 真实路由器上做仿真）、
     不同时间窗口/不同模型架构（多层 LSTM）的预测精度对比
  四种细粒度评估都能展示研究方法的鲁棒性。本条仍是建议项，不命中仅警告。

  **案例分析（Case Study）**特别说明：对实验中发现的具体问题（如某个特殊漏洞、
  某个失败用例、某个典型场景）做深入个案讨论，是优秀方法型论文的常见做法。
检查方法: |
  1. 消融形式：grep '消融' / 'ablation' / '.*的重要性' / '去掉.*的影响'
  2. 参数敏感性形式：grep '参数敏感' / 'sensitivity' / '不同.*下的' / '不同.*架构' / '不同.*配置' / '.*的影响'
  3. 真实部署形式：grep '生产设备' / '真实部署' / '生产环境' / '仿真实验'
  4. 案例分析形式：grep '案例分析' / 'case study' / '案例研究' / '具体案例'
  5. 任一命中即通过；都不命中仅警告（不强求）
评判标准:
  通过: 含上述任一形式的细粒度评估（可同时含多种，如倪匀博论文同时含消融+敏感性+案例分析）
  警告: 都没有（建议性，不影响通过）
  不合格: 不适用
修改建议模板: |
  "建议补充以下任一形式的细粒度评估：
   - 消融实验（去掉某模块看效果变化，如'代码数据库的重要性'专节）
   - 参数敏感性分析（不同 K 值/超参数下的指标曲线，如'不同大语言模型的适配性'）
   - 真实部署评估（在生产环境中对比效果）
   - 案例分析（对发现的具体漏洞/失败案例做深入个案讨论）
  本科论文有此一步可显著加分。优秀论文（倪匀博）甚至同时含 4 种形式。"
团队论文 override: 无
```
